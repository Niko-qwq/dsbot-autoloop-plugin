# M08 DS Bot 产品入口与通知

在 Autoloop 右栏打开「产品」。Chief 在此接入 GitHub App、确认私有产品仓库并绑定现有的长期 PM Bot 与使用 Bot。Chief 或 PM 核对版本计划后从面板确认启动。已绑定的普通私聊共用产品 Issue 记录，可查看关联版本、候选试用进度、发行与回退历史。使用 Bot 的实际运行提供浏览器预览和制品下载。需要主观判断的试用由用户通过面板确认。

`autoloop_product` 根据宿主的私聊会话和产品身份注册。使用 Bot 只能从真实用户输入所在回合开始运行或提单，重试保留原始运行身份。后端按仓库、角色、版本和授权核对命令。GitHub App 连接、产品绑定、显式启动与试用采纳使用同源网页动作。浏览器预览仅使用经回执校验的运行制品，内容安全策略隔离脚本并禁用连接。ZIP 下载返回原始制品字节。

版本任务完工、实际发行与实际回退各自生成可追查的事实。Chief 使用宿主已有的原生投递机制，投递携带固定文案与稳定事件关联。

运行 `npm run verify:module -- M08`。覆盖可信会话与原始用户输入、同源操作、跨产品制品读取、摘要篡改、原生制品下载，并在实际安装检查三个 Bot 的私聊与面板往返。

## 插件应急入口

DS Bot 左上角品牌字样旁的小图标打开 Autoloop 应急悬浮面板。入口随品牌字样显示，状态请求在打开面板后发起。Chief 私聊可用红钮发起二次确认，其他会话显示使用提示。服务端将确认绑定到当时安装的版本、批准的回退版本和配置。同一个确认只能用一次。点击确认之前只读取版本和就绪状态。

应急助手离开 DSH 进程独立运行，持久保存状态。它将修复任务交给 Codex CLI，只在任务返回匹配回执时计为接手。等待回执 60 秒，接手后最多等待 5 分钟。Codex 在独立源码检出中产出待审核改动。超时或恢复检查失败时，由宿主从固定的 SHA-256 安装包回退并独立核验重启；候选修复可在之后另行审核。Python 运行层未能启动时，已配置的 Web 应急入口会单独保留。

部署者在插件数据目录放置属主可读写的 `emergency-config.json`。`host` 指定 `dshHome`、`profile`、`dshCli`、`launchService`、`origin`、`accessFile`、`rollbackPackage`、`rollbackSha256`、`rollbackVersion`、已核实数据兼容的 `compatibleFrom`，并可指定 `storeDir`。`repair` 指定 Codex 的绝对 `executable`、本地 `sourceDirectory`、固定的 `sourceCommit` 和可选 `detail`。当前宿主回退实现针对 macOS 的 DSH Web LaunchAgent。应急状态保存在插件数据目录的 `emergency/status.json`。
