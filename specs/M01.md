# M01 GitHub App 接入

安装者在自己的 GitHub 个人或组织账户注册私有 App，选择要管理的仓库。安装步骤提交 Manifest 表单，回调通过一次性状态换取 App 凭证。主机也可通过其凭证提供方直接装载已有 App。Issue 通过后续模块轮询。

## 接口

- `createGitHubAppSetup` 返回注册表单的地址、Manifest 和回调处理器。将 `manifest` 作为 JSON 编码的表单字段提交，回调由可信主机调用 `complete({code, state})`。注册信息中的私钥只交给主机的凭证提供方。
- `createGitHubAppClient` 接收 App ID、可选 Client ID 和 RSA 私钥。后端可核验 App 和仓库、调用绑定仓库的 API、上载 Release 制品，以及撤销本进程缓存的仓库令牌。
- `verifyRepository({owner, repo})` 返回仓库 ID、安装 ID、规范仓库名称、默认分支、可见性和干净的 Git HTTPS URL。调用使用返回的仓库绑定和所需权限。返回的 API 结果保留状态码、ETag、分页链接和数据。
- `provisionPrivateRepository({owner, accountType, name})` 只请求建仓权限，并在创建后核验私有仓的 ID 与安装范围。创建成功但无法核验时返回 `LINK_REQUIRED`，供负责人检查并关联现有仓库。

按仓库 ID 和授权范围缓存短期令牌，在过期前刷新。接到 401 时重新签发一次。主动撤销会先停止在本进程签发和使用相关令牌，再撤销已签发令牌。主机层负责授权判定与持久化解绑。凭证由可信主机保管，禁止传给模型、Worker、事件总线及产品工作区。

## 独立验收

运行 `node --test tests/modules/m01_github_app.test.mjs`。使用替代 HTTP 传输验证一次性回调、RSA 签名、安装与仓库身份、令牌范围和撤销、私有建仓重试边界，以及制品上载的固定目标。真实 GitHub 验收需要安装者在测试账户完成注册和授权。
